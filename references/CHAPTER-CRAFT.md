# 章节开发指引（每章开发必读）

---

## 十条原则（一句话索引）

| # | 原则 | 一句话 |
|---|---|---|
| 1 | 16:9 固定舞台 | 内容 1920×1080 + transform scale，没有响应式 |
| 2 | 全局 step 计数器 | 章节是 step 的纯函数，无定时器 |
| 3 | 逐步揭示 | `step >= N` 或 `step === N`，每步展一步 |
| 4 | 口播节拍 = step | 一节拍 = 一 step = 一聚焦想法 |
| 5 | 隐藏的边角控件 | 进度条 / 翻页器默认 opacity 0 |
| 6 | 舞台无 chrome | 没有 header / footer / 页码 / 品牌条 |
| 7 | 内容驱动动画 | 先找内在动作，找不到才入场动画兜底 |
| 8 | 多点逐个揭示 | 1 项 = 1 step，禁同步 stagger 上 N 项 |
| 9 | 整片同一主题 | 颜色 / 字体走 token，其它尺度章节自由 |
| 10 | 双源原则 | 口播定节拍，文章定画面密度 |

## 这是视频，不是 PPT

正在做的是**视频网页** —— 讲者点击 + 口播 + 录屏发出去给观众看。
判断每一步做对没有，标准非常朴素：

- **不像 PPT** —— 观众感觉是在看视频，不是在看翻页幻灯
- **看起来舒服** —— 配色、字体、节奏都让人放松
- **有视觉冲击** —— 画面在演事情，不只是文字堆砌

---

## 必须用 CSS / SVG 绘制视觉演示

> **底线**：每章至少 1~2 处"动起来的图 / 演示元素"。整章纯文字 = 回去重做。

视频感最强的来源 —— 用户**看见**了被讲解的东西在屏幕上演给他看：

- 数字在递增 / 横条在生长 / 排名在交换
- 流程节点依次点亮 / 连线自绘
- 对比被一刀切开 / 聚光灯扫过 / 形状在变形
- 模拟终端交互 / AI 对话窗口 / 文件目录树

---

## 逐步揭示

`step >= N` 控制每步展什么。最重要的一条：

> 口播说"第一是 A、第二是 B、第三是 C"时，**严禁一个 step 全展示**。
> 一项 = 一个 step，讲完一项再亮下一项。

**step 还原则**：`narrations.ts` 的长度 **必须等于** 章节渲染最大 step 数。

---

## 双源原则

- **节奏 / 顺序** 跟口播稿 —— 关键顺序不能乱
- **画面细节 / 数据 / 引用** 回原文章抽 —— 把口播没念到的数字挂画面上
- **画面信息密度 > 口播信息密度** —— 否则就是 PPT

## 画面表现力原则

设计技巧本身无所谓好坏——判断标准只有一个：**这个技巧是否在传递内容？**

### 内容驱动的技巧（鼓励使用）

以下技巧在 ExamMaster 3.1/3.2 原始章节中大量使用且效果极佳：

| 技巧 | CSS/实现 | 原始章节用法 |
|:--|:--|:--|
| emoji 作语义标识 | `<span>☀️</span>` | 655: 光照条件图标 |
| 渐变模拟物理环境 | `linear-gradient(135deg, ...)` | 655: lab暗蓝 vs 车间暗红 |
| 数字发光强调 | `text-shadow: 0 0 20px color` | 655: 99% 绿色发光 vs 40% 红色 |
| 卡片颜色编码信息 | `border-color: green/red` | 655: 绿框=好 / 红框=差 |
| 模糊/光晕模拟物理效果 | `backdrop-filter: blur(3px)` | 655: 运动模糊 + grime 油污 |
| 动态 inline style | `style={{background: rgb(...)}}` | 661: 不同光照下头盔颜色变化 |
| 径向渐变模拟光源 | `radial-gradient(circle, ...)` | 655: 光源位置模拟 |
| 分层叠加创建景深 | 多个绝对定位 div 叠加 | 655: part + blur + grime 三层 |
| text-shadow 做标题pop | `text-shadow: 0 0 30px rgba(...)` | 655: 超大 ✕ 字发光 |
| 缩放/脉冲动画 | `@keyframes pulse { 50%{transform:scale(1.1)} }` | 用于引导注意 |

### 空洞装饰（禁止 · 每条都有"为什么"和例外）

| 元素 | 为什么是 slop | 例外 |
|:--|:--|:--|
| 紫粉对角渐变背景 | AI 语料"科技感"万能公式 | 主题本身用（如某些暗色科技主题） |
| 全场 Inter/Roboto 单字体 | 无设计感的出厂字体 | — |
| 纯黑 #000 + 纯白 #FFF | 缺少温度感 | 极致黑白主题（极少数） |
| 圆角卡片 + 左彩色 border accent | 2020-2024 烂大街 UI 模式 | 课程主题的 card primitive 就是这风格 |
| 每张卡片都配无意义 icon + tag | 装饰性填充（data slop） | icon 承载了可区分的产品信息 |
| 全章 N 步同一种入场动画 | 动画偷懒 | — |
| 每屏右下角挂 mono 角标/序号 | 无内容标签 | — |
| 编造假数据/假 Logo/假数字 | 假数据比空着更坏 | — |

### 正向推荐

- ✅ 中英文混排：`"Noto Sans SC"` / `"Inter"` / `var(--font-display-cn)` 等
- ✅ 颜色走 token（`var(--accent)` / `var(--surface)` 等），禁凭空发明 hex
- ✅ 不用纯黑 #000 → 近黑 `#0A0A0A`；不用纯白 #FFF → 近白 `#FAFAFA`
- ✅ `text-wrap: pretty` + CSS Grid 布局
- ✅ 数据数字做发光强调（`text-shadow: 0 0 20px color`）
- ✅ 一处细节做到 120%（发光/渐变/分层），其它做到 80%
- ✅ 诚实 placeholder > 拙劣假实现
- ✅ 翻看同课程已有章节 CSS，从已有上下文生长

## 布局模式速查表

画布 1920×1080 全部可用。**每章根据内容类型选择布局，连续两章不得重复同一模式。**

| 模式 | 适用内容 | CSS 关键词 |
|:--|:--|:--|
| **全版式** | 流程图/架构图/大图 | `width:100%` |
| **左右分栏** | 对比/AB 选型 | `display:flex; flex-direction:row; gap:48px` |
| **网格卡片** | 多项并列（概念/案例/工具） | `display:grid; grid-template-columns:repeat(3,1fr)` |
| **表格矩阵** | 参数对照/SOP 步骤 | `display:grid; grid-template-columns:...` |
| **非对称分栏** | 主图+侧边信息 (3:2) | `grid-template-columns: 3fr 2fr` |
| **Z 字形** | 时间线/步骤流程 | 奇数行 `flex-direction:row` / 偶数行 `row-reverse` |
| **放射/焦点** | 中心概念向外发散 | `position:absolute; transform:translate(...)` |
| **沉浸全屏** | 单一视觉主体 | 全屏背景 + 叠加文字 |

> **强制规则**：连续两章禁止同模式，每段(S1-S6)至少 3 种不同模式。
> 开发前**翻看同课程已有章节 CSS**，保持风格一致。

## 单步口播 > 10s 时的步内策略

当某 step 口播超过 150 字(~10s)时，仅靠入场动画不够。步内叠加以下技巧：

| 策略 | 做法 | 适用 |
|:--|:--|:--|
| **过程模拟** | CSS keyframes 模拟口播描述的物理过程 | "电梯下降→门开" |
| **焦点放大** | 当前讲述元素全屏展示，其余收缩 | 逐项介绍多个事物 |
| **数字滚动** | 口播提到数字时同步做 count-up 动画 | "每秒几十亿次" |
| **循环填充** | 画面边缘放低 opacity 脉冲/扫描线，不影响主体 | 口播持续 >15s |

> 优先拆步——多步短口播 > 单步长口播 + 复杂动效。

## 代码层最小约束

### 必须用 token（换主题不破）

- **颜色**：`--accent` / `--text` / `--text-2` / `--text-mute` / `--surface` / `--surface-2` / `--rule` —— 禁硬编码 hex/rgb
- **字体**：`--font-display-cn` / `--font-body` / `--font-mono` —— 禁硬编码字体名
- **主题 primitive**：`.hero-num` / `.rule` / `.card` / `.stage-frame`

### 章节 CSS 独立

- 每章独立 CSS 前缀（2-4 字母），不跨章 import
- 禁 `setTimeout/setInterval`，用 CSS keyframes
- 交互元素加 `data-no-advance`
- JSX 文本禁 `\u` 转义，直接写 UTF-8 字符

### 边距规范

- 顶部最小留空 50-70px，底部最小留空 60-80px（字幕空间）
- 内容在舞台内**垂直居中**（`.scene-pad` 已设 `display:flex;flex-direction:column`，root 追加 `justify-content:center;`），不得贴顶部排列
- 禁止用 `padding` 缩写覆盖 scene-pad，如需增减用独立 `padding-left/right` 属性
- 卡片内边距：水平 32-40px，垂直 28-36px

### narrations.ts 强制约束

- `narrations.length` = 章节代码最大 step 数
- 每个元素 = 该 step 的口播文本
- 这是**音频合成 + Auto 模式自动推进的唯一真相源**

## 完工自检（每章强制执行）

写完一章必须逐项过，不达标回去改，**禁止先放着以后修**：

- [ ] 每章至少 1~2 处 CSS/SVG 视觉演示
- [ ] 不同 step 的主导动作不一样
- [ ] 清单/列表逐项揭示，1 项 = 1 step
- [ ] 画面信息密度 > 口播信息密度
- [ ] 颜色和字体家族全部走 token
- [ ] 未使用纯黑 #000 或纯白 #FFF（用近黑/近白替代）
- [ ] 中英文混排正确（中文 Noto Sans SC / 英文 Inter）
- [ ] 没有假数据/假数字/无内容角标
- [ ] 字号 ≥ 14px，无页眉页脚
- [ ] 独立 CSS 前缀，未跨章 import
- [ ] `narrations.ts` 存在且 length = 章节最大 step 数
- [ ] 动画时长 ≤ 口播时长
- [ ] 连续两章未使用同一布局模式
- [ ] 口播 >150 字的 step 用了 ≥1 种步内动态策略
- [ ] 画面中有 ≥1 处发光/强调/动态驱动的文字或数字效果

## 常见反馈速查

| 反馈 | 定位层 | 修复方向 |
|:--|:--|:--|
| "没有动态效果" | 视觉 | 加 CSS 关键帧动画 / 交互元素 / 数字滚动 |
| "全是居中列排布" | 布局 | 换一种构图模式(分栏/网格/全版/Z字形) |
| "画面太挤" | 间距 | 增 padding/gap，删多余元素 |
| "信息太少" | 内容 | 回原文章抽细节挂到画面 |
| "风格和前章不一样" | 一致性 | 参考前章 CSS 的间距/圆角/字号 |
