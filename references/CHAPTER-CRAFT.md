## 十条原则（一句话索引）

| # | 原则 | 一句话 |
|---|---|---|
| 1 | 16:9 固定舞台 | 内容 1920×1080 + transform scale，没有响应式 |
| 2 | 全局 step 计数器 | 章节是 step 的纯函数，无定时器 |
| 3 | 逐步揭示 | `step >= N` 每步展一步。旧元素可位移保留（积累模式）或整屏替换（替换模式） |
| 4 | 口播节拍 = step | 一节拍 = 一 step = 一聚焦想法 |
| 5 | 隐藏的边角控件 | 进度条 / 翻页器默认 opacity 0 |
| 6 | 舞台无 chrome | 没有 header / footer / 页码 / 品牌条 |
| 7 | 内容驱动动画 | 先找内在动作，找不到才入场动画兜底 |
| 8 | 多点逐个揭示 | 1 项 = 1 step，禁同步 stagger 上 N 项 |
| 9 | 整片同一主题 | 颜色 / 字体走 token，其它尺度章节自由 |
| 10 | 双源原则 | 口播定节拍，文章定画面密度 |

## 这是视频，不是 PPT

正在做的是**视频网页** —— 讲者点击 + 口播 + 录屏发出去给观众看。
判断每一步做对没有，标准非常朴素：

- **不像 PPT** —— 观众感觉是在看视频，不是在看翻页幻灯
- **看起来舒服** —— 配色、字体、节奏都让人放松
- **有视觉冲击** —— 画面在演事情，不只是文字堆砌

---

## 必须用 CSS / SVG 绘制视觉演示 + 提供交互

> **底线**：每章至少 1~2 处动起来的图或演示元素。元素全部展示后，画面中必须有
> 可点击、可拖拽或可切换的交互点。整章纯文字或长时间零交互 = 回去重做。

视频感最强 —— 用户看见画面在演：
- 数字在递增 / 横条在生长 / 排名在交换
- 流程节点依次点亮 / 连线自绘
- 对比被一刀切开 / 聚光灯扫过 / 形状在变形
- 粒子聚拢成形 / 噪声背景流动 / 字符雨下落
- 模拟终端交互
- 模拟 AI 对话窗口
- 模拟文件目录树

交互感最强 —— 用户自己动手参与：
- 点击元素看见隐藏信息 / 点击按钮切换状态
- 拖拽滑块改变参数 / 点击节点展开详情
- 选择选项得即时反馈 / 悬停卡片浮现案例

怎么组合发挥都行 —— 但每章必须用。

## 逐步揭示

`step >= N` 控制每步展什么。最重要的一条：

> 口播说"第一是 A、第二是 B、第三是 C"时，**严禁一个 step 全展示**。
> 一项 = 一个 step，讲完一项再亮下一项。

**step 还原则**：`narrations.ts` 的长度 **必须等于** 章节渲染最大 step 数。

---

## 双源原则

- **节奏 / 顺序** 跟口播稿 —— 关键顺序不能乱
- **画面细节 / 数据 / 引用** 回原文章抽 —— 把口播没念到的数字挂画面上
- **画面信息密度 > 口播信息密度** —— 否则就是 PPT

## 画面表现力原则

设计技巧本身无所谓好坏——判断标准只有一个：**这个技巧是否在传递内容？**

### 内容驱动的技巧（鼓励使用）

以下技巧在完整的课件设计中效果极佳：

| 技巧 | CSS/实现 | 适用场景 |
|:--|:--|:--|
| emoji 作语义标识 | `<span>☀️</span>` | 概念列表配分类标识 |
| 渐变模拟环境 | `linear-gradient(135deg, ...)` | 实验室 vs 车间 · 白天 vs 夜晚 |
| 数字发光强调 | `text-shadow: 0 0 20px color` | 关键对比数值做发光效果 |
| 卡片颜色编码信息 | `border-color: green/red` | 好/坏 · 对/错 视觉区分 |
| 模糊/光晕模拟物理效果 | `backdrop-filter: blur(3px)` | 运动模糊 · 油污 · 雾化 |
| 动态 inline style | `style={{background: rgb(...)}}` | 数据驱动颜色的动态渲染 |
| 径向渐变模拟光源 | `radial-gradient(circle, ...)` | 光源位置 · 舞台聚光 |
| 分层叠加创建景深 | 多个绝对定位 div 叠加 | 图层叠加 · 前景/背景分离 |
| text-shadow 做标题 pop | `text-shadow: 0 0 30px rgba(...)` | 超大符号 · 强调文字 |
| 缩放/脉冲动画 | `@keyframes pulse { 50%{scale:1.1} }` | 引导注意 · 强调当前元素 |

> 更多正向设计建议（字体栈、色彩、反 AI slop 速查）→ `references/DESIGN-SYSTEM.md`

### 空洞装饰（禁止）

> 详细的反 AI slop 约束 + 正向推荐 → `references/DESIGN-SYSTEM.md`

### 正向推荐

- ✅ 中英文混排：`"Noto Sans SC"` / `"Inter"` / `var(--font-display-cn)` 等
- ✅ 颜色走 token（`var(--accent)` / `var(--surface)` 等），禁凭空发明 hex
- ✅ 不用纯黑 #000 → 近黑 `#0A0A0A`；不用纯白 #FFF → 近白 `#FAFAFA`
- ✅ `text-wrap: pretty` + CSS Grid 布局
- ✅ 数据数字做发光强调（`text-shadow: 0 0 20px color`）
- ✅ 一处细节做到 120%（发光/渐变/分层），其它做到 80%
- ✅ 口播提到真实场景/界面 → 主动向用户索取素材
- ✅ 没有素材时用 CSS 视觉模拟，不编造假图
- ✅ 诚实 placeholder > 拙劣假实现
- ✅ 翻看同课程已有章节 CSS，从已有上下文生长

> 反 AI slop 速查 + 字体栈 + 色彩约束 → `references/DESIGN-SYSTEM.md`

## 布局模式速查表

画布 1920×1080 全部可用。**每章根据内容类型选择布局，连续两章不得重复同一模式。**

| 模式 | 适用内容 | CSS 关键词 |
|:--|:--|:--|
| **全版式** | 流程图/架构图/大图 | `width:100%` |
| **左右分栏** | 对比/AB 选型 | `display:flex; flex-direction:row; gap:48px` |
| **网格卡片** | 多项并列（概念/案例/工具） | `display:grid; grid-template-columns:repeat(3,1fr)` |
| **表格矩阵** | 参数对照/SOP 步骤 | `display:grid; grid-template-columns:...` |
| **非对称分栏** | 主图+侧边信息 (3:2) | `grid-template-columns: 3fr 2fr` |
| **Z 字形** | 时间线/步骤流程 | 奇数行 `flex-direction:row` / 偶数行 `row-reverse` |
| **放射/焦点** | 中心概念向外发散 | `position:absolute; transform:translate(...)` |
| **沉浸全屏** | 单一视觉主体 | 全屏背景 + 叠加文字 |

> **建议规则**：连续两章不建议使用同一布局模式，每段(S1-S6)至少尝试 3 种。
> 开发前**翻看同课程已有章节 CSS**，保持风格一致。

## 空间编排：步间的画布舞蹈

内容不应滞留在居中竖条内。画布是 1920×1080 的舞台，元素可以分布在
不同区域，step 推进时上一帧的内容可以位移缩放，也可以整屏替换。
**根据知识点关系选择编排模式。**

### 两种空间模式

| 模式 | 规则 | 适用 |
|:--|:--|:--|
| **积累模式** | 旧元素位移到边缘/角落，新元素在焦点区域出现；所有内容就位后整体均衡 | 知识点有递进关系 · 构建论证链 · 展示多个概念如何关联 |
| **替换模式** | step N 替换 step N-1，上一帧清空 | 独立知识点 · 交互演示 · 测验 · 需全屏聚焦 |

**两种模式可在同一章内混合。**

### 字体参照画布

不要被 `max-width` 容器限制字号。参照画布实际尺寸——标题在 1920 宽的
屏幕上大到能看清即可，正文在三分之二画布宽度内舒适阅读即可。

### 技术要点

- `position: absolute` + `transition: all 0.6s` 实现步间位移
- `transform: translate()` + `scale()` 同时位移和缩放
- 积累模式：元素通过 CSS class 切换改变位置/大小

## 单步口播较长时的步内策略

当某 step 的口播超过约 150 字（参考 SKILL.md 口播建议每步 200-400 字，
较短步不触发此策略）时，画面需要在整段语音播放期间保持动态感。
设计思路从简到繁：

1. **拆步**：将长步口播按自然断点拆为 2~3 步，每步配独立的画面内容 —— 实现最直观
2. **步内变化**：不拆步，在当前 step 内叠加内容驱动的 CSS 动画
   （数字递增 / 颜色渐变 / 连线绘制 / 场景切换……内容是什么就演什么）
3. **组合编排**：利用积累模式，让上一步元素位移到角落，释放焦点区域给新内容

> 选哪种方法由内容决定。优先拆步——多步短口播 > 单步长口播 + 复杂动效。

## 代码层最小约束

### 必须用 token（换主题不破）

- **颜色**：`--accent` / `--text` / `--text-2` / `--text-mute` / `--surface` / `--surface-2` / `--rule` —— 禁硬编码 hex/rgb
- **字体**：`--font-display-cn` / `--font-body` / `--font-mono` —— 禁硬编码字体名
- **主题 primitive**：`.hero-num` / `.rule` / `.card` / `.stage-frame`

### 章节 CSS 独立

- 每章独立 CSS 前缀（2-4 字母），不跨章 import
- 禁 `setTimeout/setInterval`，用 CSS keyframes
- 交互元素加 `data-no-advance`
- JSX 文本禁 `\u` 转义，直接写 UTF-8 字符
- 超过 50 章时 Component 使用 `React.lazy(() => import(...))`，按需加载避免首屏下载全量 bundle。narration 文本保持静态 import（体积小）

### 边距规范

- 顶部最小留空 50-70px，底部最小留空 60-80px（字幕空间）
- 内容在舞台内**垂直居中**（`.scene-pad` 已设 `display:flex;flex-direction:column`，root 追加 `justify-content:center;`），不得贴顶部排列
- 禁止用 `padding` 缩写覆盖 scene-pad，如需增减用独立 `padding-left/right` 属性

### narrations.ts 强制约束

- `narrations.length` = 章节代码最大 step 数
- 每个元素 = 该 step 的口播文本
- 这是**音频合成 + Auto 模式自动推进的唯一真相源**
