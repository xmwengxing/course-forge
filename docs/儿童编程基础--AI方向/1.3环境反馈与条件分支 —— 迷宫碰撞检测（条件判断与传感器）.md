### 📋 第3课《环境反馈与条件分支 —— 迷宫碰撞检测（条件判断与传感器）》教学设计方案（录播极客版）

#### 一、 教学目标
1. **知识目标**：理解**开环控制（Open-loop）** 与**闭环控制（Closed-loop）** 的本质区别；掌握**条件分支结构（Conditional Branching / If-Else）** 的执行逻辑；理解**传感器（Sensor）** 在程序中提供**布尔值（Boolean）** 的作用。
2. **技能目标**：熟练运用“侦测”模块进行**碰撞检测（Collision Detection）**；能够编写包含“如果...那么...否则”的多分支逻辑脚本；初步构建基于“感知-决策-执行”范式的简单交互系统。
3. **态度目标**：建立“代码必须考虑边界条件与异常处理”的工程严谨性；初步领悟AI智能体“感知环境并做出决策”的底层运行机制。

#### 二、 教学方法设计（录播课适配）
* **Bug重现导入（20%）**：展示角色“穿墙而过”的经典物理引擎Bug，引出“开环控制”的缺陷，激发引入“传感器反馈”的需求。
* **双轨制概念映射（30%）**：PPT强制展示 `[生活常识] ➡️ [专业术语]`。例如：`[如果下雨就带伞] ➡️ [条件分支 (If-Else)]`；`[碰到墙壁] ➡️ [碰撞检测 (Collision Detection) / 布尔值 (Boolean)]`。
* **录屏实操与“暂停”指令（30%）**：演示键盘事件与碰撞检测的结合，设置强制暂停点，要求学生完成迷宫空气墙的搭建。
* **架构升华（20%）**：将简单的“碰墙反弹”升华为机器人学中的 **“感知-决策-执行（Sense-Plan-Act）”** 范式，为后续AI课程做认知铺垫。

#### 三、 评价方法设计（基于柯氏四级评估模型 - 录播异步版）
* **L1 反应层**：视频中途弹出的“逻辑判断题”（如：当传感器未碰到墙壁时，If-Else代码块会执行哪一部分？）。
* **L2 学习层**：课后通关任务——提交一段“迷宫寻宝”的实操录屏。要求：角色受键盘控制，碰到黑墙必须反弹（无法穿墙），碰到金色终点触发“胜利”状态。
* **L3 行为层**：社群异步挑战——“致命陷阱设计：在迷宫中加入‘红色岩浆’，要求使用多分支条件（Else-If），实现‘碰黑墙反弹，碰红岩浆直接重置坐标到起点’。截图发群比拼谁的迷宫最硬核。”
* **L4 结果层**：彻底打破“线性执行”的思维定势，建立起基于“环境状态（State）”进行“逻辑分支（Branching）”的计算思维。

**讲师口播（语气专业、直击痛点）：**
“各位屏幕前的小工程师们，大家好，我是翁老师。
在前两节课中，我们学习了‘顺序执行’和‘循环结构’。只要写下代码，CPU就会不知疲倦地执行。
但是，这种执行方式存在一个致命的缺陷。大家看屏幕上的这段演示：角色在迷宫里移动，遇到墙壁，它居然直接‘穿墙’过去了！在很多劣质游戏中，这被称为‘穿墙Bug’。

为什么会穿墙？因为目前的程序处于一种叫做 **【开环控制（Open-loop Control）】** 的状态。
什么是开环？就是程序只管自己发号施令（比如‘向前移动10步’），它**完全不关心外界环境发生了什么变化**。哪怕前面是悬崖，它也会照样往前走。

在真实的软件工程，尤其是人工智能和机器人领域，这是绝对不允许的。一辆自动驾驶汽车如果‘闭着眼睛’开，后果不堪设想。
今天，我们要给程序装上‘传感器’，学习计算机科学中极其核心的 **【条件分支结构（Conditional Branching）】**，让程序从‘开环’走向‘闭环’，具备感知环境并做出决策的能力。”

#### 【08:00-20:00】概念映射：布尔值、传感器与If-Else逻辑
**(PPT画面：
展示映射卡片：
1. 【生活中的选择】 ➡️ 【条件分支 (If-Else Statement)】
2. 【是/否、真/假】 ➡️ 【布尔值 (Boolean / True or False)】
3. 【碰到颜色/边缘】 ➡️ 【碰撞检测 (Collision Detection) / 状态侦测】)**

**讲师口播：**
“要让程序变聪明，我们需要引入两个核心概念。

**第一，传感器与布尔值（Boolean）。**
在Scratch的浅蓝色‘侦测’模块中，有很多像雷达一样的指令，比如 **【碰到颜色 [黑色]？】**。
请注意这个指令的形状，它是两端尖尖的菱形。在计算机逻辑中，这种菱形代表它只会输出两种结果：**True（真/是）** 或者 **False（假/否）**。这种只有真和假的数据类型，在计算机科学中被称为 **【布尔值（Boolean）】**。
当角色挨着黑墙，传感器返回 True；当角色在空地上，传感器返回 False。这就是程序感知环境的方式，我们称之为 **【碰撞检测（Collision Detection）】**。

**第二，条件分支（If-Else）。**
有了布尔值，程序怎么做决策？我们需要橙色的控制模块：**【如果 < > 那么 ... 否则 ...】**。
它的底层逻辑非常严谨：CPU会先计算尖尖角里的‘布尔值’。
如果是 True，就执行‘那么’里面的代码块；
如果是 False，就跳过它，去执行‘否则’里面的代码块。
**这就是计算机的‘十字路口’，代码的执行流在这里发生了分叉。**”
